## Phase 6.5 scope — retire the legacy mirror block

The "Phase 6 bridge" comment block in `src/lib/admin-pending-publish.ts` is the target. As of 2026-05-12 it lives at lines ~116–136 of that file. It writes 11 legacy columns alongside the `published_*` columns at admin approve time:

```
item_name, brand, category, condition, sale_price, description,
seo_title, seo_description, negotiable, product_type, barcode
```

With the public site fully cut over (PRs #40, #44, #45), no reader consumes these legacy columns anymore for display purposes. The mirror is dead-code at the write path and the drift risk we set out to eliminate.

### What the PR should do

1. **Delete the mirror block** in `src/lib/admin-pending-publish.ts` — the lines explicitly bracketed by the `Phase 6 bridge — remove when public site reads published_* directly` header and the `End Phase 6 bridge` trailer.
2. **Keep the legacy columns in the table.** Column drops are destructive and need a separate PR with a migration + rollback plan. 6.5 just stops writing to them.
3. **Verify no other writer** is keeping legacy columns up to date. Worker submit (`/api/team/items`) currently writes `shop_source`/`shop_label`/`item_name=''`/`category=''` for the NOT NULL constraints — that stays. We're only retiring the *publish-time mirror*, not the worker-time stub.
4. **Verify no public-side reader has snuck back in.** Grep for `item.item_name`, `item.brand`, `item.category`, `item.product_type`, `item.description`, `item.seo_title`, `item.seo_description`, `item.negotiable` in the `src/app/` tree. CLAUDE.md's resolver rule names these specifically. Each occurrence should be either:
   - Inside `src/app/admin/*` (sacred — legacy reads OK, do not touch)
   - Inside a non-display path (filter/search/analytics) per the "Display vs Non-display" carve-out in CLAUDE.md
   - A genuine bug we need to flag separately (don't fix in 6.5)
5. **Plan the retirement of `resolvePublicItemFields()` itself.** Once the legacy columns are dropped (separate later PR), the resolver's `?? legacy_X` fallback becomes a no-op. Either keep it as a clean abstraction or delete it and read `item.published_X` directly. Decision call when 6.5 ships — not a 6.5 deliverable.
